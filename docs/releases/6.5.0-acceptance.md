# 6.5.0 release acceptance

PR #260 merged at `e7b8ccd31776addb3c1ba744d007396a2f03c672` after all
required checks passed. Code-owner approval is no longer required. The release
actor issues both receipts and pushes the annotated tag with the same account.
Publishing still needs the operator's release approval.

## Hosted-runner diagnostics

Dispatch CI with `run_release_gaps=true` and `candidate_run_id=43576556505`
to test the retained main candidate. The driver verifies every retained asset
before installation. This permits installers only when
`GITHUB_ACTIONS=true` and `RUNNER_ENVIRONMENT=github-hosted`. The driver verifies
the published 6.4.0 checksum, installs 6.5.0, binds installed
app.asar to the build, checks uninstall, installs published 6.4.0, upgrades it
in the same location, and checks preserved app data and the OFF preference.
It extracts the Portable payload and compares app.asar hashes.
It never invokes the 6.4.0 uninstaller or runs Fix now during these diagnostics.

The first unmodified hosted-runner launch failed to start renderer/GPU child
processes with error 18. Keep that failure as evidence. UI diagnostics launch
a separate runtime copy stamped asInvoker; the installed/extracted executable
stays unchanged and the copied app.asar must be byte-identical. These launches
do not prove that either native requireAdministrator executable works.

For each package, in-memory IPC faults exercise startup permission errors,
timeouts and retry in the packaged renderer. In-memory network faults exercise
the offline manual update screen. These are diagnostic injections, not proof
of a real OS permission denial. Six support-form journeys exercise the bundled
endpoint and require visible failure with each draft retained when unavailable.
The artifact contains screenshots and report.json. Test results do not establish
native final-package release eligibility.

## Native acceptance on a disposable Windows Home desktop

Use a clean VM snapshot with UAC enabled, Windows PowerShell and PowerShell 7,
Zoom Workplace installed machine-wide, and a non-helper administrator account.
Do not use the affected everyday PC. Do not disable UAC, application control,
antivirus or other security controls. An unsigned candidate blocked by policy
is a blocker; do not substitute another payload or alter security policy.

1. Download the `release-candidate-<main SHA>` artifact from successful main CI.
   Verify every manifest SHA-256, size and latest.yml installer SHA-512 before use.
   Record the Actions run ID, artifact ID and artifact digest. Use these same
   Setup and Portable bytes throughout. Rebuilds need fresh acceptance.
2. For Setup and Portable separately, observe both UAC cancel and accept on the
   unmodified executable. Record package and launched-runtime SHA-256, operation
   (install/extract), path and manifest `requireAdministrator`. Cancel must not
   run the repair. Do not infer accept/cancel from an elevated runner launch.
3. Run the existing packaged acceptance driver with exact package, source,
   runtime and operator-attestation arguments documented in its usage. Exercise
   a real helper repair; verify loaded/unknown profiles refuse teardown, cancel
   and failure recovery are truthful, and UserManager and the operator session
   stay healthy. Check Start, icons, Snipping Tool and elevation afterward.
4. Repeat clean install/uninstall and in-place 6.4.0 upgrade. Check executable,
   shortcuts, uninstall record, app data and both update preference values.
   Verify behavior after a normal reboot. Never run the 6.4.0 uninstaller.
5. Exercise actual slow/denied Windows dependencies using the existing disposable
   native fixtures. No unknown check may pass or enable Fix now. Keep actual OS
   results distinct from injected UI cases.
6. Run bug report, rating and contact on both exact packages. If support is
   unavailable, each journey must show failure and retain the draft; bind the
   endpoint configuration revision and each journey receipt to package hashes.
   A live service instead requires delivery acknowledgement evidence.
7. Validate the native and support receipts with scripts/release-evidence.mjs.
   The release actor dispatches Release evidence issuer on main for each receipt
   and sets only their immutable artifact IDs in the release variables.

## Operator release approval packet

Include source SHA, merged PR, all required check results, candidate artifact
identity, exact Setup/Portable hashes, native and support receipt identities,
release notes and signature state. Keep unrun cases explicit. No tag, draft
publication or latest-feed change is authorized by test preparation alone.
Before approval, read back active required-check/thread-resolution rules and
immutable-release support. Do not reactivate a code-owner approval requirement.
After approval, push a new annotated v6.5.0 tag at current main and let the
existing workflow verify, upload and read back its exact asset set.
