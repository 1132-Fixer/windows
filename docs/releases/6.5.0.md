6.5.0 is the first release after 6.4.0. Version 6.4.1 was prepared but never published, so this release also contains the 6.4.1 repair-safety changes listed in the [changelog](https://github.com/1132-Fixer/windows/blob/main/CHANGELOG.md).

### Startup check: "Unable to complete"

Some people on 6.4.0 saw **Unable to complete**, "The startup check did not finish in time", and "9 checks could not be verified".

In 6.4.0, if any one part of the startup check failed, the app threw away every result and showed that same sentence, whatever the real cause. It was not always a timeout, and the nine checks had not failed: they had not been verified.

In 6.5.0:

- The message names the step that stopped and says whether it timed out or could not run.
- Results from the steps that did finish are kept in **View details**. Only the affected checks read "could not be verified".
- A check that could not run is never shown as passed. **Fix now** stays unavailable until every check is verified.
- **Try again** joins the check that is already running. It cannot start a second one.
- The startup check only reads settings. It changes nothing on the computer. In 6.4.0 it could start the Windows Secondary Logon service; it no longer does.

We do not yet know what makes the step fail on the affected computers. No report or log from one reached us, because in-app feedback was not working. If 6.5.0 still shows **Unable to complete**, open **Support**, copy the report and attach it to a GitHub issue: it now includes the step and its code.

### Automatic app updates: you can turn them off

Open **About** at the bottom right. It is there on every screen, including **Unable to complete**.

- **Automatic app updates** switch.
  - **Off:** 1132 Fixer does not check for, download or install updates on its own. Nothing installs when you exit.
  - **On:** the app checks when it starts and every four hours. You choose when to download. A downloaded update installs after a short countdown or when you exit. This is how 6.4.0 behaved.
- **Check for updates** button. It works with the switch off. It only looks: a download needs **Download update**, and an install needs **Restart now**.

The switch is **on** until you change it, the same as before. Your choice is saved at once and is kept when you restart the app, restart Windows or install a newer version. If you turn the switch off during a restart countdown, the countdown stops and the update waits for **Restart now**. An install that has already started cannot be stopped safely, and the app tells you so.

In 6.4.0 an update you postponed with **Later** still installed when you closed the app. With the switch off, that no longer happens.

### Other changes from 6.4.1

- Rebuilding the helper account no longer restarts shared Windows profile services ([#252](https://github.com/1132-Fixer/windows/issues/252)).
- Startup stays on **Checking…** until the first check reports. It no longer shows **Ready to fix Zoom** first.
- A failed Windows tool check no longer turns into several false "missing tool" errors.

### Signing

This release is not code-signed. Windows SmartScreen will warn, and Smart App Control will block it. See [code signing](https://github.com/1132-Fixer/windows/blob/main/docs/security/code-signing.md).
